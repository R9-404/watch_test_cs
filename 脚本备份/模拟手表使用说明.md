# 模拟手表使用说明（阶段2）

真机还没到，先用这个脚本"假装"成一块手表，按真实手表的方式把数据发给后端，
这样网页上的**心率血压、睡眠步数、位置信息、摔倒告警**都会实时变化。

## 一、怎么启动

1. 先确认后端已启动（双击「启动系统.bat」，或单独「启动后端.bat」）。
2. 双击项目根目录的 **「启动模拟手表.bat」**。
3. 看到类似下面的输出就说明跑起来了：

```
[2026-10-12 19:48:15] 第 8 次上报  心率=145  血压=146  步数=1488  位置=113.062086,28.19744  ★ 心率异常 / 血压异常
```

按 `Ctrl+C` 停止。

## 二、看哪里

用管理员账号 `15179158704 / 123456` 登录 → http://localhost:8087/

| 页面 | 会看到什么 |
| --- | --- |
| 基础管理 → 设备管理 | 设备在线/离线、电量、最后心跳、最后位置；可生成绑定码、重置密钥 |
| 健康管理 → 心率血压 | 每个老人最新的心率/血压，异常时标记；点"详细情况"看曲线 |
| 健康管理 → 睡眠步数 | 步数、睡眠时长随上报变化 |
| 健康管理 → 位置信息 | 经纬度滚动更新，"是否摔倒"在跌倒演示时变红 |

## 三、常用参数

```bat
rem 换一台设备（设备号/密钥在「设备管理」里看）
启动模拟手表.bat --deviceNo WATCH0002 --secret demo-secret-2

rem 只上报正常数据（不演示异常）
启动模拟手表.bat --scenario normal

rem 改上报间隔（秒）
启动模拟手表.bat --interval 5

rem 手表与电脑不在同一台机器时：把 server 改成电脑的局域网 IP
启动模拟手表.bat --server http://10.239.21.82:8795

rem 先绑定再上报（绑定码在「设备管理」里生成）
启动模拟手表.bat --bind 952KP3
```

也可以直接改 `watch-sim\watch-sim.config.json`，把默认值写死：

```json
{
  "server": "http://127.0.0.1:8795",
  "deviceNo": "WATCH0001",
  "secret": "demo-secret-1",
  "intervalSeconds": 3,
  "scenario": "demo",
  "startPoint": { "lng": 113.0625, "lat": 28.1975 }
}
```

## 四、演示模式（scenario=demo）的行为

按 `正常 → 心率血压偏高 → 正常 → 摔倒告警 → SOS呼叫 → 正常 ...` 循环，
每段持续几秒到十几秒，方便在页面上看到异常和告警。

- **正常**：心率 62–92、血压 105–132、步数持续累加、位置缓慢移动
- **心率血压偏高**：心率 118–145、血压 142–165（超过后端阈值 110 / 140，页面标记异常）
- **摔倒告警**：带 `alarm=1` 上报，"位置信息"页显示"摔倒"（红色）
- **SOS**：模拟长按 SOS 按钮，后端记录告警（日志里能看到"收到 SOS 呼叫"）

## 五、环境要求

- 用项目内置的 Node（`tools\node-v10.24.1-win-x64`），无需另装；系统里装了 Node 10+ 也能直接跑。
- 脚本只依赖 Node 内置模块（http / fs / path），不需要 `npm install`。
- 后端地址必须是**手表能访问到的地址**：同机用 `127.0.0.1`，跨设备用电脑局域网 IP。

## 六、常见问题

| 现象 | 原因与处理 |
| --- | --- |
| `登录失败：设备号或密钥不正确` | 设备号/密钥填错，或该设备被删除；到「设备管理」核对 |
| `上报被拒绝：设备还未绑定老人` | 该设备没绑定；到「设备管理」生成绑定码，用 `--bind 绑定码` 绑定 |
| `上报失败：connect ECONNREFUSED` | 后端没启动，或 server 地址写错 |
| 页面数据不动 | 看模拟手表窗口有没有输出；再确认登录的是"管理员"端（家属端只看自己家老人） |
| 位置信息页时间列显示的是告警时间 | 正常：该列展示的是最近一次事件时间，跌倒后会更新为告警时间 |
