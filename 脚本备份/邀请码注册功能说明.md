# 邀请码注册功能 —— 实现说明

## 一、功能概述

本次在原有的「管理员/家属」账号体系上，新增了**邀请制自助注册**：

1. 管理员登录系统后，在「后台管理 → 邀请码管理」中选择一位老人，生成邀请码（可设置有效期、可批量生成）。
2. 管理员把邀请码发给家属（微信/短信均可）。
3. 家属打开登录页，点「注册账号」，填写邀请码 + 自己的姓名、关系、性别、手机号、密码、地址。
4. 校验通过后系统自动创建家属账号，并**自动绑定邀请码指定的老人**，家属用手机号+密码即可登录家属端。

邀请码为**一次性**使用：注册成功后立即失效；同时支持有效期（留空表示长期有效）和作废。

## 二、数据库改动

新增一张表 `invite_code`（已加入 `old.sql`，同时也提供了升级脚本）：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | int(10) 自增 | 主键 |
| code | varchar(20) 唯一 | 邀请码（8 位大写字母+数字，已去掉 0/O/1/I 等易混淆字符） |
| old_id | int(10) | 绑定的老人ID，家属注册后自动关联该老人 |
| create_user | varchar(20) | 生成人（管理员账号） |
| create_time | datetime | 生成时间 |
| expire_time | datetime | 过期时间，NULL 表示长期有效 |
| used | tinyint(1) | 0-未使用，1-已使用 |
| used_time | datetime | 使用时间 |
| used_family_id | int(10) | 使用该邀请码注册出来的家属ID |

升级方式（二选一）：

- 双击 `升级数据库（添加邀请码）.bat`（推荐，脚本自动建表）。
- 命令行执行：`mysql -uroot -p123456 --default-character-set=utf8mb4 old < invite_code_migration.sql`

> 全新部署时直接双击「一键导入数据库.bat」即可，`old.sql` 里已经包含该表。

### 接口清单（全部为 POST + JSON，返回值风格与原有接口一致）

| 接口 | 权限 | 入参 | 说明 |
| --- | --- | --- | --- |
| `/restful/inviteCode/oldPersonList` | 管理员 | 无 | 老人下拉列表 |
| `/restful/inviteCode/list` | 管理员 | state: all/unused/used/expired | 邀请码列表 |
| `/restful/inviteCode/create` | 管理员 | oldId、count(1~50)、expireDays、createUser | 生成邀请码 |
| `/restful/inviteCode/delete` | 管理员 | id | 作废未使用的邀请码 |
| `/restful/inviteCode/checkCode` | 匿名 | code | 注册页实时校验邀请码，返回绑定老人姓名、剩余天数 |
| `/restful/inviteCode/join` | 匿名 | code、familyName、familyPhone、familyPassword、familyRelation、familySex、familyAddress | 家属注册并自动绑定老人 |

返回码沿用原有约定：`1111` 成功、`0000` 失败；邀请码场景额外区分 `0001` 邀请码不存在、`0002` 已使用、`0003` 已过期。

### 安全性说明

- 邀请码一次性使用：`update ... where id=? and used=0` 原子更新，并发下也不会被重复使用。
- 手机号唯一性校验：管理员表（users）与家属表（family）都会检查，避免同一手机号重复注册。
- 服务端做了完整校验：手机号格式（11 位、1 开头）、姓名长度、密码 6-20 位、性别合法性；前端校验只是提示，不依赖。
- 邀请码随机生成并查重，数据库层面还有唯一索引兜底。
- 日志只记录手机号/邀请码，不记录密码。
