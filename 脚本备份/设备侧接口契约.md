# 手表端（设备侧）接口契约 v1

> 本文档定义**手表端 ↔ 后端**之间的所有接口，手表 App（鸿蒙 ArkTS）与后端并行开发时以本文件为准。
> 后端已全部实现并通过模拟手表验证；手表端只需按本文档发 HTTP 请求即可。

## 0. 约定

| 项目 | 约定 |
| --- | --- |
| 协议 | HTTP（局域网演示）/ 后续可换 HTTPS |
| 方法 | 全部 `POST` |
| 编码 | `Content-Type: application/json;charset=UTF-8` |
| 字段命名 | 小驼峰（camelCase） |
| 时间格式 | `yyyy-MM-dd HH:mm:ss`（本地时间，Asia/Shanghai） |
| 成功码 | `returnCode = "1111"` |
| 失败码 | `0000` 通用失败；`0004` 设备鉴权失败；`0005` 设备未绑定；`0006` 绑定码无效 |
| 鉴权方式 | 请求体里带 `deviceNo` + `secret`（设备号+密钥），不使用登录会话 |
| 局域网地址 | `http://<电脑局域网IP>:8795`，本机演示为 `http://127.0.0.1:8795` |

所有响应都至少包含 `returnCode`，失败时额外包含中文 `message`，手表端可直接展示。

## 1. 手表端接口

### 1.1 设备登录

```
POST /restful/device/login
{ "deviceNo": "WATCH0001", "secret": "demo-secret-1" }
```

成功响应：

```json
{
  "deviceId": 1,
  "deviceNo": "WATCH0001",
  "alias": "演示手表1号",
  "bound": true,
  "oldId": 1,
  "oldPersonName": "姜涛",
  "returnCode": "1111"
}
```

- `bound=false` 表示还没有绑定老人，必须先走 1.2 绑定，否则上报会被拒绝。
- 密钥错误返回 `0004`。

### 1.2 绑定老人（手表上输入 6 位绑定码）

```
POST /restful/device/bind
{ "deviceNo": "WATCH0001", "secret": "demo-secret-1", "code": "952KP3" }
```

成功响应：`{ "oldId": 1, "oldPersonName": "姜涛", "returnCode": "1111" }`

- 绑定码由管理员在系统「设备管理 → 绑定码」生成，默认 1 天有效，一码只能用一次。
- 绑定码大小写不敏感，输入时可忽略空格和连字符。

### 1.3 心跳

```
POST /restful/device/heartbeat
{ "deviceNo": "WATCH0001", "secret": "demo-secret-1", "battery": 88, "appVersion": "1.0.0" }
```

成功响应：

```json
{
  "serverTime": "2026-10-12 19:48:00",
  "bound": true,
  "oldId": 1,
  "reportInterval": 5,
  "pendingAlarm": 0,
  "returnCode": "1111"
}
```

- 建议 30 秒一次；后台「设备管理」以 60 秒内有心跳判定为**在线**。
- `reportInterval` 是后端建议的上报间隔（秒），手表端可据此调整。

### 1.4 数据上报（核心接口）

```
POST /restful/device/report
{
  "deviceNo": "WATCH0001",
  "secret": "demo-secret-1",
  "beTime": "2026-10-12 19:48:00",
  "hr": 78,                 // 心率 bpm，可选
  "bp": 118,                // 血压（收缩压）mmHg，可选
  "step": 1693,             // 当日累计步数，可选
  "sleep": 7,               // 昨夜睡眠小时数，可选
  "sleepState": "0",        // 0-睡眠正常 1-睡眠质量差，可选
  "lng": "113.062581",      // 经度，可选
  "lat": "28.197874",       // 纬度，可选
  "source": "gps",          // 定位来源 gps/wifi/lbs，可选
  "alarm": "1",             // "1" 表示本次为摔倒/紧急告警，可选
  "battery": 73,            // 电量百分比，可选
  "appVersion": "1.0.0"     // 可选
}
```

成功响应：

```json
{ "rateState": "0", "preState": "1", "serverTime": "2026-10-12 19:48:00", "returnCode": "1111" }
```

- `rateState`/`preState` = `1` 表示后端判定心率/血压异常，手表端可据此提示或震动。
- 后端做范围校验：心率 20–250、血压 40–300、步数 ≤200000、睡眠 0–24；超范围按 0 处理（不上报该指标）。
- 未绑定设备调用返回 `0005`。
- **摔倒等紧急事件**：`alarm="1"`，后端会写一条告警记录，家属端「位置信息」页会显示"摔倒"。

### 1.5 SOS 一键呼叫

```
POST /restful/device/sos
{ "deviceNo": "WATCH0001", "secret": "demo-secret-1", "lng": "113.0625", "lat": "28.1975" }
```

成功响应：`{ "message": "已通知家属", "returnCode": "1111" }`

- 不传经纬度时使用设备最近一次上报的位置。

## 2. 后台管理接口（网页端用，手表端不需要）

| 接口 | 入参 | 说明 |
| --- | --- | --- |
| `/restful/device/list` | 无 | 设备列表（含绑定老人、在线状态、电量、最后位置） |
| `/restful/device/create` | alias、model、oldId(可空) | 登记新设备，返回 deviceNo + secret |
| `/restful/device/createBindCode` | oldId、expireDays、createUser | 生成绑定码 |
| `/restful/device/bindCodeList` | oldId | 绑定码列表 |
| `/restful/device/deleteBindCode` | id | 作废未使用的绑定码 |
| `/restful/device/resetSecret` | deviceId | 重置设备密钥 |
| `/restful/device/unbind` | deviceId | 解除设备与老人的绑定 |
| `/restful/device/delete` | deviceId | 删除设备 |
| `/restful/device/handleAlarm` | oldId | 把该老人最近的告警标记为已处理 |

## 3. 数据落到哪里（对接现有页面）

| 上报内容 | 落库位置 | 页面 |
| --- | --- | --- |
| hr / bp | `ratepre`（含 rate_state / pre_state 异常标记） | 健康管理 → 心率血压 |
| step / sleep | `watch_day_info`（每设备每天一条，当天覆盖更新） | 健康管理 → 睡眠步数 |
| lng / lat | `device_location`（每次一条流水） | 健康管理 → 位置信息 |
| alarm / SOS | `alarm_precess`（status=1） | 健康管理 → 位置信息「是否摔倒」 |
| 设备档案 | `device`（设备号、密钥、绑定、在线） | 基础管理 → 设备管理 |
| 阈值档案 | `watch_info`（hrf/hrl/bpf/bpl） | 基础管理 → 手表信息 |

## 4. 手表端实现建议（鸿蒙 ArkTS）

1. **网络层**：用 `@ohos.net.http` 发 POST，统一封装 `devicePost(path, body)`，自动带上 `deviceNo`/`secret`，并统一处理 `returnCode != 1111`。
2. **本地存储**：用 `@ohos.data.preferences` 保存 `deviceNo`、`secret`、`serverUrl`、`oldId`，首次启动进"配网/绑定"页。
3. **启动流程**：读本地配置 → `login` → 未绑定则弹绑定码输入页 → `bind` → 进入主界面 → 定时 `heartbeat` + `report`。
4. **页面建议**（466×466 圆屏，字号 ≥ 20fp，按钮 ≥ 60vp 便于老人点击）：
   - 首页：老人姓名、心率、电量、在线状态
   - 心率页：最近心率 + 简易折线
   - 位置页：经纬度 + "上报中"状态
   - SOS 页：整屏红色大按钮，长按 3 秒触发
5. **定时上报**：`reportInterval` 秒一次。注意鸿蒙后台会冻结应用，演示时保持应用在前台即可；真实产品需申请后台任务/长时任务权限。
6. **异常提示**：`report` 返回 `rateState=1` 或 `preState=1` 时震动+红字提示；跌倒检测在端侧触发后立刻带 `alarm=1` 上报。

## 5. 联调顺序建议

1. 先在本机跑通后端 + 模拟手表（`node watch-sim\watch-sim.js`），确认页面数据会动。
2. 手表端先用**模拟器**（DevEco 自带 wearable 镜像）跑通 `login → bind → report`。
3. 真机到位后，把 `serverUrl` 改成电脑局域网 IP（如 `http://10.239.21.82:8795`），手表与电脑连同一个 Wi-Fi 即可。
